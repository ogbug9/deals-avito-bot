# gpuflip — контекст для Claude Code

Поиск перекосов цен на Авито: видеокарты, целые ПК, комплектующие. Владелец: Данил (Москва). Цель: система, которая не уходит в минус по издержкам. Отвечать кратко, по-русски.

**Только поиск и алерты.** Ничего не покупать, не писать продавцам, не решать капчу, не запускать второй Chrome на том же `.chrome-profile`.

## Статус
Тесты: `python -m pytest -q` → 303 passed. Версия 0.5.0, схема базы v6. Готово: сбор через Chrome (полный обход + лёгкий цикл с защитой и лимитом запросов), база по 9 разделам, режимы поиска, глубокая карточка с кэшем, перепроверка, срок продажи по ушедшим лотам, журнал сделок, сравнение лотов и моделей, аналоги, интерфейс в `web/`, десктопное приложение и exe (`build.bat`). Покупка и продажа вручную.

## Проверено на живом Авито (2026-10-13)
- `requests` получает 429 всегда. Сбор — через настоящий Chrome (Playwright, `channel="chrome"`, профиль `.chrome-profile`). Автоматическую «проверку безопасности» (403/439) браузер проходит сам; капчу «проблема с IP» проходит только человек в окне сборщика (пропуск привязан к профилю браузера).
- 3 загрузки за ~2 минуты → капча на сутки+. Обход 18 страниц с паузой 20–40 с прошёл без капчи; при наборе базы капча пришла на 9-й странице. Не уменьшать `DELAY_SEC`.
- Параметр доставки в ссылке поиска — `d=1` (проверено: 386 из 388 карточек со значком доставки). Коды категорий — в `sources.CATEGORIES`; неверный код Авито молча уводит на родительский раздел (сборщик это ловит).
- Селекторы выдачи: фикстура `tests/fixtures/avito_search_2026-10.html`. У описания нет маркера (берётся `<p>` перед датой), адрес — `item-location`. В общероссийской выдаче адрес пуст: город берётся из адреса объявления (`/krasnodar/...`).
- Карточка: `item-view/closed-warning` + «Объявление снято с публикации» = inactive (подтверждено на реальном снятом лоте); город — в `<title>`, состояние — «Состояние: Б/у» в характеристиках.
- На 2 100 объявлениях: «ниже рынка» 6–7 кандидатов, комплектующие 6–8, срочные 1, регион 1, разбор ПК 0, плохое описание 0. Лучший кандидат ушёл меньше чем за час.

## Не проверено вживую (этап 3)
- Лёгкий цикл и защита от блокировок работали только в тестах: при сдаче этапа Авито держал капчу (добор `collect --per-category 2000` остановился на системных блоках, видеокарт 2000, ПК 549, остальное 50–260).
- Глубокая карточка в рабочем цикле (разбор проверен на сохранённых живых страницах), Telegram (нет токена), значок в трее, уведомления Windows, автозапуск, сбор из собранного exe.

## История и перезапуск
- Ничего не удаляется: ушедшие лоты остаются (`status='inactive'`, `gone_at`), даты `first_seen` / `last_seen` / `posted_at`, `price_history`, `market_history`.
- «Ушло» ставит только проверка карточки: за полный обход — кандидаты, глубокие карточки и `VERIFY_PER_CYCLE` самых давно не виденных. Открывшаяся карточка обновляет `last_seen`.
- Расписание, защита и счётчик запросов хранятся в `settings['sched.state']` и восстанавливаются при старте.
- В exe до версии от 13.10 21:20 обход падал на `print` с «⏸» (консоль cp1252) — отсюда `setup_stdio()`.

## Известные дыры
- Число объявлений продавца на карточке Авито не показано — `seller_ads` считается по нашей базе. Код продавца (`/brands/<код>`) есть только у продавцов с именем в выдаче.
- `words/analogs.json`: индексы — прикидка, не замеры; у RTX 50-й серии — «очень приблизительно».
- 14.10: `collect --per-category 1000 --cats protsessory,materinskie_platy,operativnaya_pamyat,...` добрал процессоры, платы и память до ~1000 (две капчи, вторую не прошли → 429). Диски (231) и БП (187) не добраны — продолжить той же командой с `--cats zhestkie_diski,bloki_pitaniya`.
- Разбор ПК: по-прежнему чаще всего оценена только видеокарта (в выдаче описание обрезано, процессоры часто без своего рынка).
- Платы: линейка (топ / средняя / базовая) — часть позиции (`parts.mb_key`); без неё TUF сравнивался с медианой, где ROG. «RTL» в названии = новая (магазинная коробка).
- Правки файлов через bash heredoc портят `\b` в регулярных выражениях (превращается в backspace) — править скриптом из файла.
- Разбор ПК: в выдаче описание обрезано (~250 знаков), детали часто не видны; 173 из 251 ПК дороже `MAX_PRICE`. Режим почти не срабатывает, пока карточка не перепроверена.
- Общие позиции ОЗУ/БП/дисков/плат не различают бренд (доверие «среднее»); «высокое» — только когда точная позиция с брендом набрала 10 объявлений.
- Срок продажи считается по ушедшим лотам, но «ушло» ставится только перепроверкой карточек (несколько за обход): данных мало, пока почти везде условные 14 дней.
- Пороги (`config.py`) стартовые — калибровать по сделкам (`deal`). Telegram не настроен, GitHub-репозиторий не создан (remote `origin` есть, пуша не было).
- `build.bat` должен быть только из ASCII (cmd теряет начало строк на кириллице в UTF-8).
- `pip` на этой машине не собирает `proxy_tools` (скобки в имени пользователя Windows); модуль положен в site-packages вручную из архива PyPI.

## Архитектура
- `collector.py` — Playwright + Chrome; `parse_search_html` (выдача, продавец), `parse_listing_page`/`check_listing` (карточка: статус, описание, фото, продавец, характеристики), CSV-импорт; `limiter` — потолок запросов в час.
- `schedule.py` — `Scheduler` (полный обход / лёгкий цикл), `Throttle` (×3 при капче, /2 после трёх чистых циклов), `RateLimiter`; `cli.run_due` выполняет цикл, которому пришло время (общий для `watch` и приложения).
- `sources.py` — источники: раздел + регион + фильтры → ссылка; `sources.json` правится из интерфейса; `city_from_url`.
- `normalizer.py` — видеокарты: модель, память, мобильные отдельно, опечатки, `model_source`; стоп-слова/риск/срочность читаются из `words/*.txt` (`wordlists.py`); отрицания вырезаются до поиска слов. Майнинговые P104/P106 — свои позиции; GeForce 7600 GS и т.п. — не Radeon RX; модель не берётся из описания, если в названии другая карта; `vram_mismatch` — память не как у модели. `junk_reason(title, desc, category)` — мусор (правила в `words/junk.txt`, часть зависит от раздела); `is_new` — «новая» только про саму вещь.
- `parts.py` — позиции ОЗУ, процессоров, БП, дисков, плат (сокет + чипсет + форм-фактор); `fine_key` — точная позиция с брендом; `parse_pc` — разбор ПК на детали.
- `compare.py` — сравнение лотов (лучшее/худшее, эталон, отличия, CSV) и моделей; `analogs.py` + `words/analogs.json` — похожие лоты, эквиваленты.
- `query.py` — фильтры списка → SQL (интерфейс, экспорт, уведомления по сохранённым поискам).
- `scoring.py` — net = быстрая продажа − цена·(1−торг) − издержки − заморозка − риск; оценка при n≥6, алерт при n≥10.
  `price_points`: быстрая продажа = min(медиана·0.92, нижняя четверть, медиана ушедших при ≥5, новая·0.9 при ≥3 новых,
  потолок по более сильной модели — не глубже 20% от своей медианы); `why` — объяснение по шагам для интерфейса.
- `pcparts.py` — внутренняя стоимость ПК: `parts.parse_pc` → оценка каждой детали по её рынку (или по ₽/ГБ у похожих,
  «приблизительно»), сумма = нижняя граница; хранится в `parts_json` / `parts_value`; предупреждение, если одна деталь
  дороже всего ПК. Тип памяти, если не написан, берётся по платформе (`parts.platform_ddr`).
- `modes.py` — режимы: кандидаты (`candidates`), теги и причина в `listings`, счётчики (`mode_stats`), отчёт по режимам.
- `pipeline.py` — `process` (обход, точная позиция, перекупщики, уведомления по поискам), `rescore` (пересчёт без сети; `analyze_gone` — те же правила для ушедших лотов, статус и даты не меняются), `recheck` (глубокая карточка по предфильтру + перепроверка кандидатов).
- `db.py` — SQLite, схема v6; рынок позиции — по б/у при ≥6 (`used_only`), `new_low` — от скольки продают новую; перед миграцией копия в `backups/`, суточная автокопия с ротацией 7; `liquidity` по сроку жизни ушедших лотов; журнал сделок, исключения, настройки вида.
- `ui.py` + `web/` (index.html, app.css, core/list/panel/compare/tabs.js) — интерфейс (stdlib http.server, только 127.0.0.1; токен Telegram наружу не отдаётся); `app.py` — pywebview + pystray + фоновый `Worker`.
- `paths.py` — папка данных одна для exe и для запуска из проекта: `%APPDATA%\gpuflip` (или `GPUFLIP_HOME`); `adopt()` — разовый перенос старой базы из папки проекта; `setup_stdio()` — вывод не роняет сбор. Данных в папке проекта больше нет.
- `cli.py` — app / ui / collect / scan / watch / rescore / report / probe / deal.

## Дорожная карта
1. (сейчас) Пройти капчу в окне сборщика, проверить вживую лёгкий цикл и глубокую карточку; неделя теста режимов: `report --by-mode`.
2. Купить/продать вручную ≥20 сделок с учётом всех издержек; ROI > 0.
3. Полное описание ПК и состояние — через перепроверку карточек кандидатов; оценка «ушло» для ликвидности.
4. Фаза 2: шаблон первого сообщения и торг (полуавто, с подтверждением) — только после п. 2.

## Риски
Условия Авито запрещают парсинг и массовые сообщения (баны); налоги — перепродажа это ИП, не самозанятость; обман/брак — тест-стенд, без предоплаты; оборотный капитал 15–30 тыс. ₽ минимум.

## Правила
Секреты только в `.env` (в git не коммитить). Любое изменение нормализатора/скоринга/режимов — с тестом. Перед изменением схемы БД — копия (делает `db.connect`).
