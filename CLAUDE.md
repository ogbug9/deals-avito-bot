# gpuflip — контекст для Claude Code

Автономная система перепродажи видеокарт с Авито. Владелец: Данил (Москва). Цель: система, которая не уходит в минус по издержкам. Отвечать кратко, по-русски.

## Статус
Фаза 1 готова и покрыта тестами (`python -m pytest -q` → 56 passed): collector → normalizer → рынок/ликвидность → скоринг → отбор → Telegram. Покупка и продажа вручную.

## Проверено на живом Авито (2026-10-13)
- `requests` получает 429 всегда. Сборщик работает через настоящий Chrome (Playwright, `channel="chrome"`, постоянный профиль `.chrome-profile`). Автоматическую «проверку безопасности» (403/439) браузер проходит сам; капчу «проблема с IP» проходит только человек в окне сборщика (пропуск привязан к профилю браузера, не к IP).
- 3 загрузки страницы за ~2 минуты → капча на сутки+ (почасовые повторы блокировку не снимают). 5 страниц с паузой 15–30 с прошли. Не уменьшать `DELAY_SEC`, не гонять probe/scan подряд.
- Селекторы `parse_search_html` сверены с реальной вёрсткой: фикстура `tests/fixtures/avito_search_2026-10.html`. У описания нет своего маркера (берётся `<p>` перед датой), адрес — `item-location`.
- Первый обход: 247 объявлений, 167 распознано, удовлетворительных кандидатов 0 (единственный алерт оказался браком — фильтр доработан).

## НЕ проверено / известные дыры
- Полный обход невозможен: в выдаче 100+ страниц, `MAX_PAGES=5` → `complete` всегда False → `gone` не ставится, ликвидность не считается (везде `default_days_to_sell`). Нужна другая оценка «ушло» (например, по объявлениям, пропавшим из первых N страниц при сортировке по дате — не годится; скорее точечная проверка карточек).
- Рынок считается по тем же объявлениям без проверки описаний вручную; при n=6 медиана шумная.
- Пороги (`config.py`: торг 10%, прибыль ≥1500 ₽ и ≥15%, ask_to_sale 0.92) — стартовые, калибровать по реальным сделкам (`deal buy/sell/stats`).
- Telegram не настроен (работаем с `--dry-run`), GitHub-репозиторий не создан (remote `origin` прописан, пуша не было).

## Архитектура
- `collector.py` — Playwright + реальный Chrome; `parse_search_html` — разбор выдачи; CSV-импорт как запасной путь.
- `normalizer.py` — модель/память/флаги из текста; брак, ПК, ноутбуки, «куплю» отсекаются; отрицания («без артефактов», «не майнилась») вырезаются до поиска стоп-слов; модели с разной памятью без указанного объёма не оцениваются.
- `db.py` — SQLite; `baseline=1` у объявлений первого обхода источника (возраст неизвестен → не идут в ликвидность); `gone` ставится только после ПОЛНОГО обхода.
- `scoring.py` — net = продажа − цена·(1−торг) − издержки − заморозка − риск; scam при цене < 45% рынка; предоплата = отказ.
- `sources.py` — источники сбора (раздел + регион + фильтры → ссылка Авито); `sources.json` правится из интерфейса. `SEARCH_URLS` в `.env` больше не используется.
- `pipeline.py` — оркестрация; модель и прибыль считаются только для категории `videokarty`, остальные разделы пишутся в базу с признаками `defect`/`wanted`.
- `ui.py` + `ui.html` — локальный интерфейс (stdlib http.server, 127.0.0.1:8765): фильтры по базе, настройка источников, запуск обхода.
- `cli.py` — ui/collect/scan/watch/report/probe/deal.

## Дорожная карта
1. (сейчас) Парсер проверен. Накопить базу 1–2 недели (`watch`, 1–2 страницы раз в 15–20 мин).
2. Купить/продать вручную ≥20 сделок с учётом всех издержек; ROI > 0.
3. Фаза 2: шаблон первого сообщения и торг (полуавто, с подтверждением в Telegram).
4. Фаза 3: автообъявления и переоценка цены по ликвидности.
5. Фаза 4: автономная покупка — только после 50+ сделок.
6. Расширение: целые ПК (сумма комплектующих − скидка на сборку), другие комплектующие (CPU, RAM, SSD).

## Риски
Условия Авито запрещают парсинг и массовые сообщения (баны); налоги — перепродажа это ИП, не самозанятость; обман/брак — тест-стенд, без предоплаты; оборотный капитал 15–30 тыс. ₽ минимум.

## Правила
Секреты только в `.env` (в git не коммитить). Любое изменение нормализатора/скоринга — с тестом.
