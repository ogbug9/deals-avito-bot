# gpuflip — контекст для Claude Code

Поиск перекосов цен на Авито: видеокарты, целые ПК, комплектующие. Владелец: Данил (Москва). Цель: система, которая не уходит в минус по издержкам. Отвечать кратко, по-русски.

**Только поиск и алерты.** Ничего не покупать, не писать продавцам, не решать капчу, не запускать второй Chrome на том же `.chrome-profile`.

## Статус
Тесты: `python -m pytest -q` → 141 passed. Готово: сбор через Chrome, база по 9 разделам, пять режимов поиска + «ниже рынка» + список «проверить вручную», перепроверка карточек, локальный интерфейс, десктопное приложение (окно, трей, фоновый сбор). Покупка и продажа вручную.

## Проверено на живом Авито (2026-10-13)
- `requests` получает 429 всегда. Сбор — через настоящий Chrome (Playwright, `channel="chrome"`, профиль `.chrome-profile`). Автоматическую «проверку безопасности» (403/439) браузер проходит сам; капчу «проблема с IP» проходит только человек в окне сборщика (пропуск привязан к профилю браузера).
- 3 загрузки за ~2 минуты → капча на сутки+. Обход 18 страниц с паузой 20–40 с прошёл без капчи; при наборе базы капча пришла на 9-й странице. Не уменьшать `DELAY_SEC`.
- Параметр доставки в ссылке поиска — `d=1` (проверено: 386 из 388 карточек со значком доставки). Коды категорий — в `sources.CATEGORIES`; неверный код Авито молча уводит на родительский раздел (сборщик это ловит).
- Селекторы выдачи: фикстура `tests/fixtures/avito_search_2026-10.html`. У описания нет маркера (берётся `<p>` перед датой), адрес — `item-location`. В общероссийской выдаче адрес пуст: город берётся из адреса объявления (`/krasnodar/...`).
- Карточка: `item-view/closed-warning` + «Объявление снято с публикации» = inactive (подтверждено на реальном снятом лоте); город — в `<title>`, состояние — «Состояние: Б/у» в характеристиках.
- На 2 100 объявлениях: «ниже рынка» 6–7 кандидатов, комплектующие 6–8, срочные 1, регион 1, разбор ПК 0, плохое описание 0. Лучший кандидат ушёл меньше чем за час.

## Известные дыры
- Разбор ПК: в выдаче описание обрезано (~250 знаков), детали часто не видны; 173 из 251 ПК дороже `MAX_PRICE`. Режим почти не срабатывает, пока карточка не перепроверена.
- Позиции ОЗУ/БП/дисков не различают модель (доверие «среднее»); материнские платы — только чипсет, кандидатов по ним нет.
- Срок продажи не измеряется (`default_days_to_sell`), «ушло» ставится только перепроверкой карточек (3 за обход).
- Пороги (`config.py`) стартовые — калибровать по сделкам (`deal`). Telegram не настроен, GitHub-репозиторий не создан (remote `origin` есть, пуша не было).
- `pip` на этой машине не собирает `proxy_tools` (скобки в имени пользователя Windows); модуль положен в site-packages вручную из архива PyPI.

## Архитектура
- `collector.py` — Playwright + Chrome; `parse_search_html` (выдача), `parse_listing_page`/`check_listing` (карточка), CSV-импорт.
- `sources.py` — источники: раздел + регион + фильтры → ссылка; `sources.json` правится из интерфейса; `city_from_url`.
- `normalizer.py` — видеокарты: модель, память, мобильные отдельно, опечатки, `model_source`; стоп-слова/риск/срочность читаются из `words/*.txt` (`wordlists.py`); отрицания вырезаются до поиска слов.
- `parts.py` — позиции ОЗУ, процессоров, БП, дисков, плат; `parse_pc` — разбор ПК на детали.
- `scoring.py` — net = продажа − цена·(1−торг) − издержки − заморозка − риск; оценка при n≥6, алерт при n≥10.
- `modes.py` — режимы: кандидаты (`candidates`), теги и причина в `listings`, счётчики (`mode_stats`), отчёт по режимам.
- `pipeline.py` — `process` (обход), `rescore` (пересчёт без сети), `recheck` (перепроверка карточек).
- `db.py` — SQLite, схема v3; перед миграцией копия в `backups/`; статус `active`/`inactive`; история цен и медиан.
- `ui.py` + `ui.html` — интерфейс (stdlib http.server, только 127.0.0.1); `app.py` — pywebview + pystray + фоновый `Worker`.
- `paths.py` — домашняя папка данных: текущая при запуске из проекта, `%APPDATA%\gpuflip` у exe.
- `cli.py` — app / ui / collect / scan / watch / rescore / report / probe / deal.

## Дорожная карта
1. (сейчас) Неделя теста режимов: `report --by-mode` — какой режим даёт живых кандидатов.
2. Купить/продать вручную ≥20 сделок с учётом всех издержек; ROI > 0.
3. Полное описание ПК и состояние — через перепроверку карточек кандидатов; оценка «ушло» для ликвидности.
4. Фаза 2: шаблон первого сообщения и торг (полуавто, с подтверждением) — только после п. 2.

## Риски
Условия Авито запрещают парсинг и массовые сообщения (баны); налоги — перепродажа это ИП, не самозанятость; обман/брак — тест-стенд, без предоплаты; оборотный капитал 15–30 тыс. ₽ минимум.

## Правила
Секреты только в `.env` (в git не коммитить). Любое изменение нормализатора/скоринга/режимов — с тестом. Перед изменением схемы БД — копия (делает `db.connect`).
